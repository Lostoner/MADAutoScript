# 日常工作台阶段 A：实现与验收

2026-11-13 · 源码实现及自动验证完成，交由用户手工测试。

## 可以直接体验的变化

- 日常任务改为连续列表；添加指令常驻顶部，保存和撤销常驻底部。名称、参数摘要、执行状态分层，保留复制、重命名、移除和排序。
- 运行面板优先展示执行对象、具体指令、问题及恢复动作；简要日志不再默认铺满堆栈，完整日志仍可查看和复制。
- 失败定位对应那一条重复指令；「继续本轮」「正在停止…」「查看今日计划」「核对素材结果」随真实上下文变化。
- 本轮结束但还有扫荡余项时明确提示；素材尾扫已完成共享目标时，不保留首扫的旧余项提示。
- 暖白／石墨主题和字体入口统一；计划页原生输入、时间控件和复选框修正深色显示。窄窗口保留主操作和错误摘要。

计划／素材仍从原弹窗进入。配置 schema、游戏脚本、调度算法、冻结与回执存储均未修改；保存目标仍默认应用，但不启动消费。本次未构建或替换已发布的 0.8.0 便携包。

## 在本机启动新源码

先正常关闭旧 MAD 工作台。PowerShell 中运行以下命令，将新源码连接到原本机运行目录的配置和进度；不要同时打开旧工作台操作同一模拟器。

```powershell
& 'G:\projects\二游相关\MADAutoScript\.venv\Scripts\python.exe' `
  'G:\projects\二游相关\MADAutoScript\repository\main.py' `
  --data-dir 'G:\projects\二游相关\MADAutoScript'
```

本机源码目录的 `runtime/ocr` 已链接到原运行目录的现有 OCR，未下载或复制旧程序；保留原运行目录即可继续使用。若原配置开启了自动计划，打开工作台后仍会按原规则自动执行。只想看界面时，使用另外的测试数据目录；不要沿用自动计划配置。

## 用户手工测试

1. 展开一条扫荡，修改并撤销次数；复制到末尾、改名、排序并保存。检查原实例与副本参数、MAX 和剩余次数仍独立正确。
2. 用自行选定的小范围任务运行，确认运行来源、当前指令和停止反馈；结束后继续，检查未重置余项。自动计划开启时，首页主按钮应打开今日计划，而不是执行旁边的普通列表。
3. 遇到体力不足时，确认实际消耗最大可用次数后转入下一功能，页面保留剩余次数。遇到普通失败时，用「定位这条指令」检查对应实例、展开详细日志，然后按原恢复流程继续。
4. 仅在自然出现待核对时检查其入口：核对前不应重复消费。无需为了 UI 验收主动制造不明消费。
5. 在自己的 Windows 缩放和主题下检查长名称、中文输入法、键盘展开／排序和小窗口。普通参数输入 Enter 不应折叠行；Tab 焦点应可见。

MuMu 实机路径由用户接手；本轮未验证物理多屏切换、系统中文输入法组词或屏幕阅读器。阶段 B 的三主页面迁移与阶段 C 的设置／退出保护仍待后续实施。
