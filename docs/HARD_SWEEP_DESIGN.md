# HARD 扫荡：独立指令，复用现有执行链

2026-11-21 · 设计稿，尚未实施

## 1. 玩家如何使用

在「添加指令」中选择「困难扫荡（HARD）」，按区域勾选关卡，为每关设置次数或 MAX，保存后按列表顺序执行。可以复制到末尾，也可以加入某一天的计划。

采用独立任务 `mad.hard_sweep`，不把普通扫荡改成带难度开关的混合任务。这样 NORMAL 和 HARD 可以分别排序、分别保存进度，旧普通扫荡和素材扫荡仍明确使用 NORMAL。

第一版包括：

- 区域分类、多关卡选择、顺序调整、次数／MAX、区域缩略图。
- 单次日常、重复指令、持续模式、计划模式、现有 CLI 的任务选择。
- 体力不足和单关次数用尽的区别处理；结算后保存实际完成次数。

不增加：自动推图、自动补星、体力购买、次数购买／重置、HARD 素材目标规划、新调度器或外部总控接口。

## 2. 现有代码与数据依据

- `normal_sweep.navigate()` 已解决「先切难度，再读取该难度记忆的区域」的问题。`material_sweep` 也调用此函数，并使用 `check_locked=True`；这个入口和 NORMAL 默认行为需要保留。
- `sweep_utils.run_plans()` 已负责顺序扫荡、原生最大次数读取、数量夹取、体力不足、结算记账和余项保存；`SweepSelector` 已提供完整的选关编辑界面。
- 加入 `SWEEP_TASKS` 后，配置进度、日切刷新和计划模式的余项／待核对处理可以沿用现有实现。
- 项目已采集的 **ONEstore 1.11.6 配表**中，主线 HARD 为 **15 个区域，每区 4 关，共 60 关，每次 20 体力**。这些是该版本配表的统计，不代表已经实机验证当前客户端。配表中的区域图与现有主线区域图可复用。
- 该关卡表未提供可直接使用的单关每日次数字段。执行时读取游戏原生可扫上限，不预设「每天 3 次」等常量。

数据依据：本地 `artifacts/material-catalog-20261111/upstream/public/data/stages.json`，对应已采集的 MAD-Viewer 固定版本 `c312e4e305cc57441e5bd615224642ea9b2168ce`。

## 3. 最小模块划分

```text
日常任务列表 / 计划编辑器 / 现有 CLI
                   │
      TASKS 注册 + 原有参数与进度存储
                   │
       hard_sweep.implement() 薄入口
                   │
       sweep_utils.run_plans() 共用执行
          ├─ 主线导航：难度 → 区域
          ├─ 关卡搜索、三星及可扫状态
          ├─ 原生 MAX → 设置次数 → 确认
          └─ 结算 → complete_sweep() → 下一关
```

| 部位 | 设计改动 |
| --- | --- |
| 任务注册与默认参数 | 新增 `mad.hard_sweep`，加入 `SWEEP_TASKS`；默认不启用、关卡为空 |
| 关卡目录 | 增加 `hard_zones` 和 HARD 体力成本；`stage_options()` 显式识别新类型，避免落入现有弗拉瑞默认分支 |
| 执行入口 | 只新增 `module/hard_sweep.py` 薄入口，调用共用扫荡流程 |
| 主线导航 | 在现有 `sweep_utils` 内抽出一个带难度参数的小函数；保留 `normal_sweep.navigate()` 的签名与返回约定作为 NORMAL 包装入口 |
| 界面 | 新任务接入已有 `SweepSelector`；区域图复用，文字始终显示 HARD，不复制一个选择器 |
| 进度与计划 | 沿用按 `instance_id` 保存的 `unfinished_tasks`、日切刷新、冻结日及回执，不另存一套 HARD 进度或次数账本 |
| 分发 | 更新关卡目录导出白名单，保留 `hard_zones`；现有打包流程带入新入口与展示映射 |

仍使用现有 `normal_stage` 页面标识表示「地区制霸」页面，不为 HARD 复制一套相同的页面入口和截图区域。难度选中状态与页面识别分开判断。

### 参数保持现有格式

示例仅展示结构，不作为默认执行计划：

```json
{
  "plans": [
    {"stage_id": "hard:5-1", "count": 2},
    {"stage_id": "hard:5-2", "count": "max"}
  ]
}
```

`hard:5-1` 与 `normal:5-1` 是不同关卡。新 HARD 参数必须属于 HARD 目录；不借本次新增能力收紧旧普通配置的读取条件。新增关卡默认次数仍为 1，玩家可改为 MAX。

## 4. 执行顺序与边界

1. 读取本指令的剩余计划；为空时按现有规则跳过。
2. 进入地区制霸，明确切换到 HARD 并确认选中态；不能用「NORMAL 未选中」代替 HARD 正向确认。
3. 切换后重新读取区域，再导航到目标区域。不能先根据 NORMAL 记忆的区域计算移动方向。
4. 搜索完整的 `HARD 区域-关号`，确认目标关卡、三星条件和扫荡按钮状态。
5. 打开确认页，通过游戏 MAX 控件读取本次可扫上限。固定次数取剩余需求与上限的较小值；MAX 使用该上限。复读最终次数，不推算实际消费。
6. 收到明确结算后，按实际完成次数写入原有进度，再转到下一关。

确认消费不参与通用的重复点击／重试循环。复用现有 `start_sweep(before_confirm=...)` 的单次确认路径；确认后若超时或结果无法确认，转为当前运行失败并提示核对，而不是重新打开并确认同一批。

| 实际情况 | 本轮处理 |
| --- | --- |
| 配置 5 次，游戏当前最多允许 2 次 | 先扫 2 次；未完成的 3 次保留。区分是资源不足还是本关限次，再决定继续其他关卡 |
| 当前体力不足任何后续关卡的一次消耗 | 结束这条 HARD 指令，保留余项，继续后续领取等功能 |
| 只有当前关卡次数用尽，其他关卡仍可执行 | 跳过当前关卡，继续后续关卡，不把它当成全局体力不足 |
| MAX 成功扫完当前可用额度 | 该项本轮完成；不循环尝试购买次数，也不把 MAX 解释成无限扫荡 |
| 开始时可扫次数为零 | 不确认、不虚报完成；保留余项并注明原因。本次不反复打开同一关，也不改变其他扫荡任务的 MAX 语义 |
| 已确认未解锁或未达扫荡条件 | 保留该关、说明原因，继续其他可扫关卡；不尝试自动战斗 |
| 难度、区域、关号或次数无法确认 | 不继续消费，走现有失败提示；不能把识别失败当成资源不足或已经完成 |
| 出现购买／补充／重置次数页面 | 退出，不确认购买 |
| 扫荡确认后结算不明 | 不猜测完成次数、不盲目重发确认；停止当前运行并提示核对，计划模式沿用现有 `needs_review` 流程 |

同一 HARD 关卡出现在多个指令时，每个指令的计划与进度独立，但执行上限以游戏当时实际状态为准，不在脚本中复制或扩充游戏次数。

共用导航改造须保留原有调用约定：普通导航成功可返回 `None`，素材的 `check_locked=True` 路径返回布尔值。执行器不能新增 `if not navigate(...)` 而把旧成功路径当成失败；未确认目标区域时不得继续选关。

## 5. 兼容与范围

- 新建配置可以带默认关闭的空 HARD 卡片；旧任务列表不强行插入、不改变排序，玩家从「添加指令」加入。
- 使用现有默认参数合并，不为一个新任务升级配置 schema。NORMAL 关卡、重复指令、素材目标和已完成次数不改写。
- 日切仍遵守现有开关和时刻；开启时按原配置重建新一天计划，不把昨日余项额外累加。
- 已保存的日期、模板和冻结日不自动增加 HARD；玩家只在可编辑日期中主动添加。
- HARD 加入现有任务注册后供现有 CLI 选择，不顺带实现上轮讨论的外部「运行今日计划」接口。
- 素材优先级扫荡仍只规划原来的普通关卡。本轮不引入 HARD 掉落、限次约束或新的权重分配模型。

## 6. 只验证差异与受影响的共用行为

实施时复用现有测试夹具和用例，不复制一套 HARD 测试引擎，也不逐关做 60 次实机验证。

1. **难度与关号**：补 NORMAL → HARD、HARD → NORMAL 且记忆区域不同的用例；核对 HARD 完整关号，失败时不触发确认。保留素材调用普通导航的回归。
2. **次数边界**：在现有扫荡边界夹具中增加 20 体力、固定数被夹取、MAX、零次数和「单关限次后继续下一关」组合；确认结算才记账。
3. **参数与进度集成**：一个用例覆盖 HARD 添加／复制／保存重开、NORMAL 进度不变，以及计划内 HARD 余项沿用现有处理。目录检查用程序一次核对完整 ID、数量和成本即可。
4. **界面与实际页面**：复用现有选择器检查新增任务的分组、缩略图和保存值。实机先只校准难度选中态、HARD 关号／三星位置、可扫次数与确认页，取消退出；真实扫荡结算由玩家手测，或另行授权后只做必要样本。

实施前仍需从当前客户端确认：HARD 页签的选中态、列表／星级布局，以及限次为零时的按钮或提示。若布局与普通页一致，直接复用；只为实际不同的部分添加识别资源。
