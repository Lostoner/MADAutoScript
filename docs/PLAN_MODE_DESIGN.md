# MAD 计划模式：按游戏日安排日常

设计基准 · 2026-11-04 · 本地开发版已实现；真实账号运行与实际跨日待玩家验收。

## 1. 玩家怎样排出第一周

在主界面选择「计划」→「新建计划」。默认展示从今天起连续 7 个**游戏日**，可改起止日期。选中第一天，点「从当前日常复制」，保留熟悉的任务卡片、顺序和参数。编辑好后点「复制到其他日期」，勾选接下来六天，再单独打开周六修改扫荡关卡。预览显示哪些天有什么任务、几点可开始，保存即可。保存草稿不会立即操作游戏。

例如，11 月 4 日至 10 日可以这样排：

| 游戏日 | 安排 | 玩家操作 |
| --- | --- | --- |
| 11/04 至 11/06 | 日常材料：普通扫荡 → 一键领取 → 领完清体力（指定关卡 MAX） | 配好 4 日，一次复制到 5 日、6 日 |
| 11/07 | 周末培养：更换首扫材料关，保留领奖和尾扫 | 从 6 日复制，只改首扫 |
| 11/08 | 休息 | 标记休息，不执行游戏操作 |
| 11/09 至 11/10 | 恢复日常材料 | 从 4 日复制到两天 |

默认用滚动七日视图，可跨月、翻周、选择结束日期。超过 7 天时，在日期旁提示「已安排 14 天。活动和资源需求可能变化，建议一次安排不超过 7 天。」数字随长度变化；提示不阻止保存、启用或继续添加日期。一次配置适用于明确的日期，排满七天不会自动变成每周循环。

## 2. 一日任务、日期和模板

**一日任务**是一份有名称的有序指令清单。它包含指令类型、实例编号、名称、启停、参数、顺序及必要的原有前后置引用。相同类型可以多次出现，首扫和尾扫仍是两条独立指令。与日期有关的开始时间属于日程，不属于游戏指令。

**日历**属于一个玩家配置，一个游戏日只有一个安排。允许「未安排」「休息」「已排任务」；前两种都不启动游戏，但“休息”表示玩家有意留空，批量填充空白日期时保留它。已排任务却没有任何启用指令时，在预览中直接提示。计划到期后停止触发，提示「计划已结束 · 延长计划」。

**模板**是可选捷径。任意一天都能「另存为模板」，以后可选择「标准日」「只领奖」「周末刷材料」等自定义模板。放入日历时立即生成独立副本，改模板、删模板或改某一天，都不反向修改已排日期。复制只带配置，不带剩余次数、执行结果、已领取标记、断点或下次到期时间。日内引用只指向副本中的对应指令。

**批量编辑规则：**

- 单日复制到多个日期，默认只填未安排日。若目标已有安排或为休息，预览列出将被替换的日期，玩家可在同一操作中选择替换；保存前可以撤销。
- 「复制这周到下一周」按相对日期复制一段排期（包括休息日和每日开始时间）。复制单日任务内容时，保留目标日的开始时间，避免改任务时顺带改掉闹钟。
- 未来日期可独立修改、移除、改为休息，即使今天的步骤正在运行也可编辑未来。过去日期只读；可作为复制来源，只取原任务配置。
- 今天尚未启动时可完整编辑。**首版在今天首次启动时冻结整份配置**，暂停、失败、部分完成均不解锁覆盖；允许停止、恢复、查看结果或复制到未来。这样不会把已购买、已约会、已扫荡的步骤变回待执行。局部修改已开始日的未执行步骤可后续评估。

## 3. 游戏日、开始时间和错过的日期

日历按服务器游戏日划分，默认北京时间 04:00。例如 11/05 03:59 仍属于 11/04，04:00 才进入 11/05。排期表显示游戏日边界及其时区；某一天若设为 02:00，应标为「次日 02:00」。新计划沿用已有服务器时区和日切时间；普通模式关闭日切时，不改其设置，仅在启用计划前明确计划使用的边界。启用期间固定该边界，变更只用于后续尚未开始的排期，不重算历史。

每份计划有一个默认开始时间，日期可覆盖。默认可执行时间为当天日切后；玩家也可设为例如 09:00。提供两个动作：

| 动作 | 行为 |
| --- | --- |
| 开始／继续今日 | 玩家现在执行当前游戏日，即使还没到自动开始时间；已有断点则恢复。已执行的日期显示结果，不整轮重跑。 |
| 启用自动执行 | 工作台保持打开时，等待当天开始时间。若已过开始时间但仍在该游戏日，执行今天一次。启用预览明确显示「今天将立即执行」或下次启动时间。 |

错过整个游戏日的安排标为「已错过」，不补跑，不把次数叠加到今天。没有安排、休息、计划结束时都不回退到普通日常。首版无需安装后台服务；关闭程序或电脑关机期间不执行。MuMu 未启动时显示「待设备」，不记完成；设备就绪后在当天恢复检查，过日切则按新日期处理。玩家点「停止今日」后，本日等待手动继续；「暂停计划」则连未来的自动触发也暂停。

## 4. 一天怎样执行和恢复

日历只负责选择日期和启动时机。当天执行沿用现有**单次运行**：按列表顺序执行启用的指令，原有显式前后置按单次规则展开。单条指令的持续运行间隔、到期时间和「持续运行时跟随领取」不产生第二次触发。希望领奖后清体力，直接把尾扫放到领奖之后。保留原单次规则中的禁用时段；本轮被时段过滤的指令须记录原因，可在允许时段由玩家显式续做。

| 状态或事件 | 应有行为 |
| --- | --- |
| 首次启动 | 记录当日配置版本，初始化各指令自己的剩余计划。首页显示正在执行的日期、步骤和名称。 |
| 扫荡遇到资源上限 | 以游戏实际可扫次数结算；剩余体力或能量不足以扫后续关卡时，保留余项并进入下一功能。仅当前关卡限次时，仍可处理其他可扫关卡。 |
| 领取奖励新增体力 | 尾扫使用执行时的实际体力和自己的 MAX 计划；首扫未完成的次数不抢占尾扫。 |
| 中断、重启 | 恢复同日同一份配置的断点。领奖已结束、尾扫未开始，就从尾扫继续；已确认的扫荡按实际次数扣减。 |
| 识别失败或结果待核对 | 停在出错步骤，显示名称、原因和记录入口，暂停当日自动触发。玩家处理后用「继续今日」恢复，定时器不会因为开始时间已过而不断重启。 |
| 一轮结束且仍有余项 | 标为「已执行 · 有余项」，不自动重新启动整天。提供「仅续做余项」，列出之前未执行的指令及扫荡剩余关卡；已完成的商店、约会、领奖不再执行。普通模块未提供可靠的剩余量时，不根据猜测重做。 |
| 一轮全部处理完 | 持久记录「已结束」及摘要。重开软件、切换页面或再次到达触发时刻，都不重跑。 |
| 下一游戏日到达 | 停止派发昨日的新步骤。已发起的操作先核对回执，确认的结果归昨日；归档昨日剩余，再按新日期初始化。未确认的购买等有副作用的操作记为「待核对」，不自动重试；同一设备状态不明时先恢复到可识别页面。 |

普通模式仍可独立使用。一份玩家配置同时只有一个执行者；启用计划守候时，界面不同时启动普通持续运行。切换模式先在步骤边界停妥现有执行。普通模式已经跑过今天、而日历尚未执行时，不把两个模式的进度硬合并：首次启用时若有当天普通运行记录，默认从明天自动开始，玩家仍可明确选择今天执行。计划内不复用普通模式的「开始新一轮」来清空已执行日期。

## 5. 界面如何呈现

- **首页**保留普通日常入口，增加「计划」。启用后首页直接显示「今天：日常材料 · 4/5 条已处理」「下一步：领完清体力」「明天：周末培养 · 09:00」；在今天没有任务时说明最近的已排日期。玩家不必打开日历才能知道脚本接下来会做什么。
- **排期页**左侧为按游戏日排列的七日列表：日期、星期、日程名称、开始时间和状态。右侧直接复用现有指令卡片；页首始终显示正在编辑的具体日期。切换日期保留草稿，统一保存或撤销。
- **保存前预览**只突出有意义的差异：哪些日期新增、替换、休息，是否超过七天，以及启用后第一次何时运行。禁止把已开始或过去的安排作为覆盖目标。
- **记录页**按游戏日查看实际使用的配置、每条指令的名称、完成次数、跳过原因及余项；历史显示当时的名称和参数，不跟随之后的模板修改。

## 6. 开发结构与兼容

建议增加每个 profile 独立的计划配置（模板、按日期的安排和启动规则）与按游戏日保存的运行记录，按需创建。普通配置目前为 schema 6；没有使用计划的玩家照常启动，不需要先建模板、开日切或迁移成七天排期。

执行时为当天建立独立的任务配置和进度读写对象，将它传给现有 worker、任务模块及调度器。运行身份至少区分「玩家配置、模式、游戏日、指令实例」。普通与计划可以共用设备连接设置、OCR、扫荡结算和卡片编辑器，但计划不能覆盖普通模式的 `routine`、`unfinished_tasks`、`event.json` 或 `next_tick`。日期切换由计划控制，避免普通日切逻辑在原日期的上下文里重建计划。

日期记录保存配置快照、启动/终止状态、已确认步骤、剩余关卡和运行记录位置。应先持久化当日结束状态，再清理临时断点：现有 `RoutineCheckpoint.finish_pass()` 会在一轮结束时清掉断点，因此“没有断点”不能用来判断当天还没跑。对账号购买等已发送但没有确认回执的操作，保留待核对信息，不承诺凭本地断点重建游戏侧结果。

## 7. 开发顺序与验收

1. **先做按日期手动运行。** 能从当前日常生成一日任务、复制整天、独立编辑和保存日期，再通过同一个工作台执行今天。验收：周六的修改不影响周五与模板；重复扫荡实例在同日、跨日都不共用进度。用当前“首扫 → 领奖 → 尾扫”作为第一条端到端用例。
2. **再做日历守候。** 加入开始时间、设备等待、暂停、日切、缺席和计划结束。验收：03:59/04:00 正确归日；过了 09:00 当日还能启动；隔三天重开只执行当天；正常结束后连续重启不会重购；在领取后中断只恢复尾扫。
3. **最后完善批量编排。** 支持独立模板库、多日期覆盖预览、复制整周和长计划提示。验收：7 天无超期提示，14 天可保存启用；批量修改未来日期不影响正在执行的今天，休息日不被默认填满，计划结束不自动重复。

首版交付包括以上三步。无限周循环、根据掉落自动改排、唤醒电脑及多个计划争用同一账号不列入首版。实机验收分别查看一次当天完整执行与一次真正跨日的日期归属；时钟模拟负责覆盖其他边界。
