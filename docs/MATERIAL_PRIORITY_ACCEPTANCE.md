# 素材优先级扫荡：实现与验收

2026-11-19 · 源码实现及自动验证完成，交由用户手工测试。

## 已实现

- 默认只勾选素材，选择顺序决定优先级；支持跨分类顺序编号、拖动、上移／下移、Alt+方向键，保存后直接用于后续轮次。
- 按原始排序权重分配有限扫荡次数，同关取最高权重且只计一次预算；不根据掉率、预计产出或纯次数素材库存改变安排。
- 每项独立开启「达标停止」，开启才要求数量和库存观察；旧目标保持开启，数量、版本、达成状态和已冻结旧轮次保留。
- 每次调用独立配额；同一步重试续原余项，尾扫和持续调度的新周期分别规划。计划显式续做库存目标不会重发纯次数素材配额。
- 确认前保存批次，看到结果后先结算次数；库存失败不重放。消费未知仍需核对，确认次数不明后结束受影响指令本轮额度。
- 任务、首页和计划日以次数债务及可选库存条件判断余项，普通勾选不会永久显示未达标。

沿用原配置和进度入口，没有启动真实玩家配置、连接 MuMu 或执行实机消费；没有构建或替换已发布的 0.8.0 包。

## 自动验证

Windows / 项目 Python 3.11 / PyQt5，`QT_QPA_PLATFORM=offscreen`。全部测试使用隔离目录和替身游戏操作。

**110 个不同测试通过**。关联回归先完成 108 项；随后补充零头体力和库存专用续做的权重用例，最终素材核心 53 项及受影响的 3 项界面测试复核通过，未重复计数。

主要证据：

- 3∶2∶1、10 次分为 5/3/2；2 次分为 1/1/0。5∶4∶3∶2∶1 在 70 和 79 体力下均分 2/2/1/1/1，9 点零头不影响分配。
- 真实内置目录中耳环／帽子／项链／信用点、4-1 与 5-1 的例子分为 8/6，共消费预算 140；信用点不递归提权。
- 已规划 10 次实际完成 6 次，后续邮箱仍执行；显式续做只完成剩余 4 次，不重复邮箱。同位置出现序号、前后调用、根指令、持续周期与重启身份分别验证。
- 混合库存目标中途达标只重排未消费预算；未知库存仅影响相关项，纯次数观察不调用库存读取。
- 指定／排除来源、0 次和有限上限、共同掉落、换来源、未知消费、已见结果后的读取失败及重复结算均覆盖。
- 旧定义只读加载不落盘，首次保存备份旧文件；重复保存不改备份，冻结快照、完成记忆和普通配置进度保留。
- 分类选择、数量关闭保存、排序、草稿丢弃、库存开关的即时反馈、冻结次数表、日常／首页状态、计划复制与冻结、普通扫荡边界和日切回归通过。

## 手工测试建议

1. 先关闭旧 MAD 工作台，再用现有「启动新版MAD.cmd」启动源码版；原配置与进度沿用。**原自动计划开关仍然生效**，仅想查看界面时先暂停自动计划。不要同时运行新旧工作台。
2. 打开素材窗口，检查旧数量、暂停项和顺序；旧库存条件仍开启。新增素材应无需数量。若要把旧项也改成纯次数，使用「更多 → 全部关闭库存停止条件…」并保存。已有冻结轮次继续旧规则，修改在后续轮次生效，不要为了看新界面清空进度。
3. 先做不消费的检查：分类多选、排序、保存重开；点「刷新可扫关卡和体力」，核对来源和体力。该操作不应确认扫荡；仅按次数分配时不应打开素材库存提示。
4. 第一次实际试跑建议只留一个纯次数素材，把本条指令「本轮最多」设为 **1**，并保留大部分体力。确认只消费允许的一次，之后继续下一条日常；安排完成不等于取消素材勾选。
5. 再测试可选库存条件：同步一项已持有素材，把目标设为不高于实际库存，验证不消费并标记达成；关闭条件后不再被这条旧达成记忆阻止。需要再补货时用「重新开启」。
6. 小额度验证首扫／领奖／尾扫，以及自然停止后的恢复。计划模式再检查「仅续做余项」：有限次数债务继续原安排，已用完配额的库存目标仅续刷未达标项。不必故意制造未知消费；自然出现时先走原核对入口。
