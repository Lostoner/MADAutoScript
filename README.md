# MADAutoScript

面向 **MAke Drama: MAD 国际服 ONEstore 版**的 Windows 日常自动化工具。使用 MuMu、ADB 截图与控制、BAAS OCR；执行框架来自 Blue Archive Auto Script，界面沿用 PyQt5 与 PyQt-Fluent-Widgets。

当前版本：**0.7.5**。本版修复普通扫荡反复选关、日切进度刷新，以及未执行却显示完成、简要日志缺少跳过原因的问题。完整说明见 [更新记录](CHANGELOG.md)。目前实测环境为 Windows x64、MuMu 12、游戏简体中文、1920×1080 横屏。其他渠道、语言、模拟器与屏幕比例尚未验收。

## 已实现的功能

| 功能 | 当前能力 |
| --- | --- |
| 任务列表 | 开关、拖动排序、参数保存、停止、继续剩余计划、定时运行 |
| 体力领取 | 收取每日累积体力 |
| 普通扫荡 | 选择多个关卡，每关独立次数，按顺序执行 |
| 弗拉瑞区域、特别采购 | 共用学院交流形式的流程，分别选择分类、关卡和次数 |
| 普通商店 | 六种金币商品、独立数量；OCR 按商品名称定位，支持售罄后的重排 |
| 指定角色约会 | 选单指定角色、每日免费次数和地点优先级 |
| 邮箱、一键领取 | 邮箱、通行证、阿米商城免费物品、每日任务、积分宝箱、成就；子功能可选 |

竞技场、活动扫荡和特殊活动领取仍为待适配项。未完成真实连续跨两次日切的长时间验收。

**开发版：领奖后再扫一次。** 在「普通扫荡」卡片中选择「复制到末尾」，把副本放在「一键领取」之后，选择收尾关卡并设为 MAX。保存后，两条扫荡各自记录关卡、次数和结果。首次扫荡即使因体力不足而只完成部分计划，也会继续领奖；尾扫使用轮到它时游戏允许的次数。若仅当前关卡次数用尽，仍会尝试有足够体力的后续关卡。

「添加指令」可添加其他已支持的任务。单次运行按列表顺序执行。持续模式中，副本可以按自己的时间运行，也可以设为跟随领取指令；跟随时只在该领取指令运行后执行，仍遵守副本的开关和禁用时段。跟随不会重置当天的剩余扫荡计划。旧的 `--tasks` 只选择原始指令；`--diagnose` 可查看编号，再用 `--run-routine --steps 编号` 单独运行某条指令。

## 开发版：排一周日常

打开工作台右上角「计划」，选中一天，点「从当前日常复制」。编辑该日的任务卡片后，用「复制到日期…」填充其他日期；副本可以独立改关卡和次数。右侧「日期操作」可设休息或将当天存为模板。「排期设置」可延长日期范围，超过七天仍可保存。

「保存排期」和「启用自动执行」是分开的。建议先用「开始／继续今日」手动试跑。启用自动执行后，请保持工作台打开；到达设置的时刻，或在当天晚开软件时，只运行当日安排。默认游戏日为北京时间 04:00 至次日 04:00。休息日、空白日、错过的历史日期都不会自动运行。要使用普通日常或其命令行入口，请先暂停计划的自动执行。

当天首次启动后，任务配置冻结，明天仍可编辑。停止后用「开始／继续今日」恢复；当日一轮结束但仍有未刷关卡时，点「仅续做余项」查看明细。若购买、约会或扫荡在中途异常退出，先按提示核对游戏里的实际结果，再决定跳过或重试。按「历史记录」查看各游戏日实际使用的配置和执行结果。

排期保存在玩家配置目录的 `plan.json`，每日配置副本、进度、回执和日志位于 `state/<配置>/plan-days/<日期>/`。普通日常的剩余次数和定时任务独立保存。

## 开发版：按素材目标扫荡

在「添加指令」中选「素材目标扫荡」，打开「编辑目标」填写希望达到的库存并保存。保存默认应用；可用「查看目标表」检查预计关卡、次数和产出，指定来源或限制这条指令本轮最多次数。目标达成后停止，不会在后来消耗素材时自动补货。

「添加素材」按装备兑换券、基础装备和通用资源分类，兑换券再按 T2～T5 筛选。图标卡片支持跨分类多选，也可直接搜索名称、部位或阶级；已添加的素材会标灰。选择页和共享目标列表都可悬停查看放大图。

首版覆盖 ONEstore 1.11.6 普通关卡的 T2～T5 装备兑换券、基础装备和信用点，共 61 种资源。T5 与信用点的完整主线来源仍标为待实机补验。先点「同步游戏数据」核对库存和可扫状态；该操作不确认扫荡。未知库存不按零计算，游戏版本不匹配时不执行素材扫荡。

多条素材指令共享目标，可排成「首扫 → 领奖 → 尾扫」。每批最多 5 次，临近达标单次执行，之后复读库存；体力不足保留目标并继续下一条日常。普通模式与计划模式共用目标和回执，复制日程不会复制出新的素材需求。用法及手工验收步骤见 [素材目标说明](docs/MATERIAL_GOALS.md)。

## 使用 Windows 便携版

1. 下载 `MADAutoScript-0.7.5-windows-x64.zip`，完整解压到可写目录。不要在 ZIP 内直接运行。
2. 双击 `启动MADAutoScript.cmd`。便携版已包含 Python、Qt、OCR，无需另装 Python。
3. 在「设置」中选择 MuMu 的 `mumu-cli.exe`，填写实例编号。ADB 路径通常可留空；若未找到，选择同一 MuMu 安装目录中的 `adb.exe`。
4. 启动该实例中的 ONEstore MAD，登录并停在游戏主页。设置游戏语言为简体中文、分辨率为 1920×1080。
5. 勾选所需任务，展开卡片配置关卡、次数和商品，调整顺序后「保存并开始」。

固定次数扫荡中，次数 **0 表示 MAX**，由游戏原生控件决定可执行数量；素材目标的「本轮最多」设为 **0 则不主动刷取该目标**。资源用尽、库存售罄属于正常结果；不会主动购买或补充体力。购买任务按你保存的商品和数量消耗金币。

「开始 / 继续」在同一游戏日保留剩余关卡。默认日切为北京时间 **04:00**，跨过该时刻后，下次开始或持续运行会自动重建每日计划；「… → 开始新一轮」用于手动重建。旧配置中空白的日切设置会补齐，已明确设置的时刻与开关保留，升级本身不清空进度。可在「设置 → 计划刷新」调整。运行时避免同时手动操作同一个 MuMu。

任务显示「完成」表示本次已完成计划；「已跳过」表示没有执行（例如本轮已无剩余关卡）；「待续」表示仍有未完成关卡。简要日志会保留具体原因。

## 从源码运行

需要 Windows x64、**Python 3.11** 和 Git。源码 ZIP 不包含运行时。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock.txt
.\.venv\Scripts\python.exe scripts\install_ocr.py
.\启动MADAutoScript.cmd
```

安装脚本固定 OCR 提交并校验每个文件的 SHA-256。日常启动不会自动下载或更新依赖。已有 OCR 可执行 `python scripts/install_ocr.py --verify-only` 离线核对。

本项目按目录运行；请保留 `src/`、`docs/ocr-runtime.lock.json` 和 `runtime/ocr/` 的相对位置，不使用 `pip install .` 代替上述安装步骤。

## 配置、升级和日志

首次打开自动生成 `config/`，不会携带发布者的设备路径、账号配置或任务进度。`config/default/config.json` 保存参数与剩余关卡，`event.json` 保存任务顺序和调度；`config/app.json` 保存主题。

升级时关闭旧程序，将新版本解压到新目录，再复制旧版 `config/` 和 `state/`。不要用旧备份覆盖已经更新的进度。原目录可保留用于回退。

0.7.5 首次读取旧配置时自动升级到 schema 5：仅为旧版空白的日切设置补齐北京时间 04:00；保留明确设置的时刻与开关、设备设置、任务顺序、参数和剩余关卡。配置升级本身不重建计划；开始运行时若已跨过日切，才按每日刷新规则重建。

含重复指令的开发版首次打开会升级到 schema 6，并备份旧配置。复制指令只复制配置，新副本从自己的完整计划开始。中断后继续同一轮时，已结束的步骤不再执行；自然结束后再次开始，扫荡只处理各自剩余的计划。

运行记录在 `runs/`，启动错误在 `state/startup-error.log`。反馈问题时可附日志和必要的局部截图，请先去除账号信息；不要上传整个 `config/` 或 `runs/`。

## 隐私与公开范围

配置、任务进度、日志和截图保存在程序本地目录。截图和 OCR 结果可能包含游戏昵称、UID、资源数量等账号信息；分享前请逐项检查。MADAutoScript 不要求填写游戏密码，登录由游戏客户端完成；截图 OCR 使用本机服务。

发布包只带代码、游戏选单数据和 34 张局部界面识别图，不带开发者的账号配置、设备路径、实机日志、完整截图或 Git 历史。关卡目录与识别图的本机采集路径在导出时移除。第三方源码中的原始版权声明和上游测试资料保持原样。

开发版另内置 61 张公开素材图标，用于分类选取和目标列表，不包含账号截图；来源记录在 `src/images/materials/provenance.json`，浏览图标不请求网络。
